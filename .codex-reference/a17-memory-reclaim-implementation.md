# LOSP Android 17 `memory.reclaim` capability hardening

## Scope and outcome

This A1 implementation is limited to `libprocessgroup` handling of the optional cgroup-v2
`memory.reclaim` interface and its optional `swappiness=<value>` syntax. It does not change task
profile policy, init configuration, process killing, cgroup teardown ordering, feature rollout,
or device-specific behavior.

Code was changed. The implementation makes expected capability absence degrade cleanly, caches
the kernel-wide optional swappiness-syntax result per `CompactMemcgAction`, and preserves visible
failures for permissions, malformed state, and genuine I/O errors.

## Current behavior discovered

`CompactMemcgAction` reads the target memcg's `memory.current`, trims the value, and writes that
amount to `memory.reclaim`. `FULL` writes only the byte amount. `FILE` appends `swappiness=0`, and
`ANON` appends `swappiness=200`.

Before this change:

- `IsValid()` used `access(F_OK)` to require `memory.reclaim`.
- `FILE` and `ANON` validity was probed by writing `0 swappiness=0`.
- The probe did not classify errno, log its failure, or remember its result.
- Execution treated every write failure except `EAGAIN` as an error.
- `EAGAIN` was silently accepted because reclaiming the full requested amount is best effort.
- No focused `CompactMemcgAction` unit tests existed.

`reclaim_memcg_before_removal` is an aconfig rollout flag. In `processgroup_platform.cpp`, the flag
is passed to `KillProcessGroup()`. When enabled, `KillProcessGroup()` performs a `FULL` reclaim
after the processes have exited and before removing the app cgroup. Its return value is not used to
change kill/removal flow. This implementation does not alter that ordering, timeout behavior,
rollout path, or the process lifecycle.

## Problems identified

1. A kernel or hierarchy without `memory.reclaim` produced an execution error even though the
   interface is optional.
2. Optional swappiness syntax rejection was rediscovered on every validity check and could cause
   repeated failed writes.
3. The prior probe did not distinguish expected optional-feature rejection from permission and
   I/O failures.
4. The accepted `EAGAIN` result was undocumented at the decision point and gave no low-severity
   diagnostic signal.
5. The behavior had no host-independent focused tests for missing/present files, generated syntax,
   or genuine write failures.

## Code changes

### `libprocessgroup/task_profiles.cpp`

- A failed execution write with `ENOENT` is considered an absent optional `memory.reclaim`
  capability only when `memory.current` still proves the target memcg exists. If `memory.current`
  is also absent, the failure remains actionable.
- `EINVAL` is classified as unsupported only for the exact optional swappiness form generated by
  `FILE` or `ANON`; the requested selective reclaim returns failure because no reclaim occurred.
  `EINVAL` from a plain full reclaim remains an error.
- `EOPNOTSUPP` is treated as capability absence. For optional syntax it is cached; for a plain
  reclaim it is accepted as an unavailable optional interface.
- `EACCES`, `EPERM`, and all other write/I/O failures remain error-level failures with their
  original errno restored before `PLOG`.
- `EAGAIN` remains a successful best-effort outcome, with a verbose diagnostic and no retry.
- Successful or `EAGAIN` optional writes establish syntax support.
- Expected missing-interface messages are verbose. Optional syntax rejection is logged at info
  level only on the transition to unsupported.

### `libprocessgroup/task_profiles.h`

- Added a three-state atomic capability cache: `UNKNOWN`, `SUPPORTED`, and `UNSUPPORTED`.
- Added narrowly scoped helpers for optional syntax classification and state transitions.

The cache belongs to each `CompactMemcgAction`. Actions loaded into the process-wide
`TaskProfiles` singleton live for the daemon lifetime, so the cache is reused across applications
of a profile. The nested-key grammar is implemented by the kernel's `memory.reclaim` write
handler, not selected per cgroup; cgroup replacement and controller activation can change whether
the file exists, but not only which keys its parser accepts. The atomic avoids data races because
profiles may be queried concurrently. Missing `memory.reclaim` itself is deliberately not cached:
interface presence can vary by cgroup and with controller activation or cgroup lifetime. Separate
ANON and FILE actions learning independently costs at most one probe per action and avoids wider
shared state.

### `libprocessgroup/task_profiles_test.cpp`

Added temp-directory tests that do not depend on the host having a particular cgroup-v2 setup:

- missing `memory.reclaim` is invalid during validation;
- missing `memory.reclaim` degrades cleanly during direct execution when `memory.current` exists;
- full reclaim writes the current usage;
- anon reclaim emits `swappiness=200`;
- file reclaim emits `swappiness=0`;
- repeated validation does not rewrite the probe after optional syntax support is learned;
- missing `memory.current` remains an error;
- a genuine reclaim write failure remains an error.

Regular temporary files cannot reproduce kernfs-generated `EINVAL`, `EOPNOTSUPP`, or `EAGAIN`,
and permission tests are unreliable when host tests run as root. No production I/O abstraction was
added solely to synthesize those errnos. Those branches require device/kernel integration testing
or a future existing syscall-fake facility.

## Errno and capability behavior

| Condition | Before | After |
|---|---|---|
| `memory.reclaim` absent, memcg present | Execution error | Expected unsupported capability; verbose and success |
| memcg/path absent | Execution error | Still an error; `ENOENT` is not swallowed |
| optional syntax succeeds | Success, reprobed by validity calls | Success and cached supported |
| optional syntax returns `EINVAL` | Error at execution / invalid without classification | Unsupported only in optional-syntax context; cached and logged once |
| optional syntax returns `EOPNOTSUPP` | Error | Unsupported; cached and logged once |
| full reclaim returns `EINVAL` | Error | Still an error |
| full reclaim returns `EOPNOTSUPP` | Error | Optional interface unavailable; verbose and success |
| reclaim returns `EAGAIN` | Silent best-effort success | Best-effort success with verbose diagnostic; optional syntax is known supported |
| `EACCES` / `EPERM` | Error | Still an error |
| other open/write/I/O failure | Error | Still an error with preserved errno |

An action whose optional syntax has been learned as unsupported avoids subsequent probe and
execution writes. Validation and execution return false in that state: returning true from
execution would falsely claim that the requested selective reclaim happened. There is
intentionally no fallback from anon-only or file-only reclaim to full reclaim, because that would
broaden the requested operation's semantics.

## Zero-byte reclaim conclusion

No zero-byte shortcut was added. `GenerateReclaimString()` already pays for the `memory.current`
read. Skipping a zero write might save one syscall in a narrow case, but the value is inherently
racy and a zero-byte write is also useful as a capability probe for optional syntax. There is no
measurement showing a meaningful teardown benefit, and making execution depend on the sampled
zero would complicate capability learning. Benchmark evidence would be required before revisiting
this.

The validation probe requests reclaim of zero bytes, so a successful probe performs no reclaim;
it only validates the nested-key grammar. `EAGAIN` means the write was parsed and accepted but the
requested amount was not fully reclaimed, so it also establishes syntax support even though that
result is not naturally producible for this zero-byte probe on regular files.

## EAGAIN conclusion

No retry was added. For cgroup-v2 `memory.reclaim`, `EAGAIN` means the kernel could not reclaim the
entire requested amount. Reclaim here is best effort, and a retry could delay process-group
teardown without guaranteeing progress. The existing success semantics are retained, now
documented and visible at verbose logging level. No benchmark is required for this preservation;
any future retry policy would require latency and reclaim-effectiveness measurement.

## Self-review and known limitations

- Error suppression is scoped to the optional interface or the exact optional syntax; it does not
  globally suppress `ENOENT` or `EINVAL`.
- Permission and ordinary I/O failures stay visible.
- The cache covers only immutable syntax support and does not cache per-cgroup file presence.
- The post-failure `memory.current` existence check is a narrow discriminator, not an atomic
  identity check. A cgroup can disappear or be replaced between the reclaim failure and the
  check; misclassifying that race as optional-interface absence is harmless because full reclaim
  is best effort and no missing-interface state is cached. Other `ENOENT` cases remain failures.
- No process kill, timeout, removal ordering, or rollout flag behavior changed.
- No zero-byte race was introduced.
- The cache is per action, so separate anon and file profile actions each learn the same kernel
  capability once. A global cache would reduce at most one additional probe but would add wider
  shared state and test/reset complexity; it is not justified.
- Synthetic errno branches are not unit-tested in this checkout because the existing
  `libprocessgroup` tests have no syscall wrapper, injectable writer, filesystem fake, hook, or
  errno-injection facility that can model kernfs error responses. Device integration coverage is
  recommended; a generic production I/O abstraction was not added solely for these tests.
- Runtime performance benchmarking is not required for adoption: the change removes repeated
  failed probes and preserves reclaim semantics. Boot/teardown log and latency observation should
  still be included in device validation.

## Recommended commit

Subject:

```text
libprocessgroup: harden optional memory.reclaim handling
```

Body:

```text
Treat a missing memory.reclaim file as an unavailable optional capability
when the target memcg still exists, while preserving errors for missing
cgroups and genuine write failures.

Classify EINVAL only for the optional swappiness syntax, handle
EOPNOTSUPP explicitly, and cache syntax support per CompactMemcgAction to
avoid repeated failed probes and duplicate logs. Keep EAGAIN as the
existing best-effort partial-reclaim result without adding teardown delay.

Add host-independent coverage for missing and present reclaim files,
full/anon/file payload generation, and genuine path failures.
```
